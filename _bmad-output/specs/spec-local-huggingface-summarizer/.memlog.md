topic: Downloadable local Hugging Face summarizer
updated: 2026-09-09T12:09
---

- (direction) User wants a future local summarization option that downloads a model from Hugging Face like Whisper models, with implementation deferred to another session.
- (decision) The local provider must work without a cloud API key, external CLI, or Ollama installation after the user explicitly downloads a supported model.
- (capability) CAP-1: A user can choose a local downloaded summarizer and use it for Summarize, Ask AI, follow-up drafts, and Enhance without sending transcript text to a network service.
- (capability) CAP-2: A user can see supported local models, their disk and hardware requirements, download progress, failures, and installed state before selecting one.
- (capability) CAP-3: The app can verify each downloaded model against a pinned manifest before marking it usable and can remove a downloaded model on user request.
- (constraint) Only a bundled, reviewed model manifest may name Hugging Face artifacts; never accept an arbitrary repository, URL, model-supplied code, or remote configuration.
- (constraint) Downloads require explicit user action, show size and free-space preflight, use an app-owned directory, and leave no selected or partially usable model after cancellation, checksum failure, or interrupted download.
- (constraint) Local inference must keep dynamic transcript and chat data in the existing trusted main-process provider path and preserve framePrompt injection defenses, cancellation, timeout, and no-write-until-success behavior.
- (constraint) The first release must not silently change existing Claude, Codex, Ollama, or OpenAI-compatible selections, and must not introduce a cloud fallback when no local model is installed.
- (question) Which embedded inference runtime and packaging/license strategy should support the first macOS Apple-Silicon release: MLX, llama.cpp, or another reviewed runtime?
- (question) Which exact Hugging Face model revision, quantization, minimum RAM, download size, and quality benchmark define the initial supported catalog entry?
- (question) Is the embedded local provider intentionally macOS Apple-Silicon-only at launch, or must Windows/Linux be supported in the same release?
- (assumption) A one-model initial catalog is sufficient if the selector can report that model's requirements and installed state accurately.
- (event) Coherence validation passed: three stable capabilities carry intent and success; constraints bend implementation; non-goals and concrete success signal are present; unresolved runtime/catalog/platform decisions are open questions.
- (event) Preservation validation passed: local downloadable Hugging Face model, no Ollama/API/CLI setup, future-session scope, model-download analogy, and unresolved runtime/model choices are represented; wrapper-only chat phrasing was intentionally omitted.
- (event) Express specification finalized for a future implementation session.
