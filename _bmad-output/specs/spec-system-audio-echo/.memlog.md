---
topic: Remove loudspeaker echo from recordings that combine microphone and system audio
goal: Keep both the user's voice and system audio intelligible without headphones
updated: 2026-09-14T10:10
---

- (direction) User needs recordings made without headphones to remain intelligible when system audio is also captured by the microphone with a short acoustic delay.
- (assumption) Express mode selected because the request states the failure and desired outcome; no separate elicitation is needed before implementation.
- (assumption) The fix covers both Record and Live saved WAV paths because both combine the same microphone and system captures; per-source live transcript lanes remain unchanged.
- (capability) CAP-1: A user can record microphone and system audio without a delayed loudspeaker copy making the saved WAV unintelligible, while retaining the user's near-field speech and system audio.
- (constraint) Use the already captured digital system-audio stream as the echo reference at the shared audio-mix stage; do not add a cloud service or a new runtime dependency.
- (constraint) Recordings with only one selected source must retain their current audio path and level behavior; echo processing must not discard frames or block the capture callbacks.
- (non-goal) Perfect cancellation for every room, speaker, microphone, or rapidly changing acoustic path is out of scope; the implementation must degrade to the existing mix when no reliable echo correlation is present.
- (non-goal) Changing source-selection UI, transcription models, diarization, permissions, or the Live per-source transcript behavior is out of scope.
- (decision) Implement one shared lightweight adaptive echo suppressor and use it in both WAV mixers, estimating the short reference delay and removing only the correlated component from the microphone before summing sources.
- (decision) Leave Apple's voice-processing flag disabled for this path because the current engine has no audio render graph and enabling it can silence microphone capture; use the exact system tap instead as the reference.
- (note) Verification must include a deterministic synthetic delayed-echo check and the existing JavaScript test suite; a real speaker-plus-microphone smoke test remains the final device-level confirmation.
- (question) What speaker volume, microphone distance, and room geometry should be treated as the supported acoustic ceiling for acceptance testing?
- (event) Self-validate coherence pass: CAP-1 has intent and success; constraints change implementation choices; non-goals are explicit; success signal is testable; capability IDs are stable; prose is lean.
- (event) Self-validate preservation pass: the user problem, affected saved WAV paths, no-headphones scope, retention of near-field speech/system audio, fallback behavior, out-of-scope areas, and device-smoke limitation are represented in SPEC.md; wrapper ceremony was omitted.
- (decision) Implemented shared AcousticEchoCanceller in AudioCapture.swift; Record and Live WAV mixers process paired mic/system chunks before the existing clipped sum, while single-source and per-source Live transcription paths remain unchanged.
- (event) Verification: swift build passed; swiftc -parse passed for the new XCTest source; npm test passed 275/275; git diff --check passed.
- (event) Verification limitation: swift test --filter AcousticEchoCancellerTests could not load XCTest because the installed CommandLineTools toolchain lacks the XCTest module; real speaker-plus-microphone smoke test remains required on the target Mac.
- (event) Spec finalized with one capability, no companions, coherence pass verdict, and preservation pass verdict.
